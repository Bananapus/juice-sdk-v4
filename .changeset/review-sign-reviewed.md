`signReviewed` signs only what the person reviewed: a Safe transaction, an ERC-2771 forward request, a Permit2 allowance or a plain message. Core builds every typed-data definition from its own constants, so no caller passes `types` or `domain`: a Safe transaction is signed for its Safe, a forward request for the chain's Juicebox forwarder (from the connected account, with a deadline no later than `relayrForwarderDeadline()`), and Permit2 for `PERMIT2_ADDRESS`. Any other kind, a Safe DELEGATECALL to anything but a recognized MultiSendCallOnly, or a chain with no forwarder is refused before the review opens. Every signature in one call shares one prompt. The review model gains `signatures`, each with its exact typed data or text, the calls it lets someone run decoded (the Safe inner call or MultiSend, the forwarded call), and Permit2's token, amount, spender and expiry rows; the model id binds them. `sendReviewed` takes `signatures` too, shows them in the same prompt as its calls, signs them after confirm and before the first send, and returns them as `signatures`. A wallet rejection (4001) while signing throws `TransactionReviewCancelledError` and returns no signature. A self-reviewing wallet (Signa) is refused with 4200 for either until it has a reviewed-signature path.
