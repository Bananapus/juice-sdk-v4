The review model shows more of what a call does. Each call names the addresses it gives a part (`roles`: spender, recipient, beneficiary, owner, operator) and the token amounts it moves or approves (`tokenAmounts`, with decimals and symbol when known). New warnings flag an unknown destination, an unlimited approval, an ownership change, a permission grant (any approval, permit or approval for all to an address the app does not name) and unknown token decimals. An `approve` or `transferFrom` that ERC-721 shares, sent to an unknown contract, carries `possible-token-id` until enrichment settles it, and `nft` names the NFT when the call is an ERC-721 one. Tuple and array arguments carry labeled `children`, so a client can show them nested. `enrichReviewModel` reads each token's decimals and symbol once per chain, leaving them null when a read fails, asks such a contract `supportsInterface(0x80ac58cd)` to tell an NFT approval from an ERC-20 one, and never changes the model's id. `decodeReviewCall` decodes raw calldata with the SDK's own ABIs (the contract's at that address first, then by selector), for callers that hold only the bytes.
