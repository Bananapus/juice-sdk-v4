`decodePayFailure` and `classifyCashOutExecutionError` name a revert only from revert data that is a known selector with exactly its arguments, or from an error viem typed against the matching ABI item with arguments of its types. Text never counts, so an error name, selector or revert data in a message or an `Error(string)` reason is not a revert, and a bare selector no longer classifies. Shortfall reverts must settle below their minimum. A shortfall that settles nothing sets `zeroFill: true` and its message suggests no setting. The new `adjustable: "minimum"` field marks the failures a lower minimum fixes (the terminal minimum only: older buyback hooks raise the same error for their own oracle floor, and the router can derive its own), and `payRetrySlippageBps(failure, currentBps)` gives the tolerance to retry with, capped at the new `PAY_MAX_SLIPPAGE_BPS` (10%). `PAY_DEFAULT_SLIPPAGE_BPS` exports `prepareUserPay`'s default. Buyback, router, permit, Permit2 and NFT overspending messages now name the check that failed and suggest only an action that changes it.
