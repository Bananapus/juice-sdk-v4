`decodePayFailure` and `classifyCashOutExecutionError` name a revert only from revert data that is a known selector with exactly its canonically encoded arguments, from the router gateway's `RouteFailed` whose hash fingerprints a known selector (reason only, no amounts), or, when an error carries no revert data, from an error viem typed against the matching ABI item with arguments of its types. Text never counts, so an error name, selector or revert data in a message or an `Error(string)` reason is not a revert, and a bare selector no longer classifies. Shortfall reverts must settle below their minimum. A shortfall that settles nothing sets `zeroFill: true` and its message suggests no setting. The new `adjustable: "minimum"` field marks the terminal and buyback hook minimums that preparing again with a larger `slippageBps` relaxes (never the router's conversion minimum), and `payRetrySlippageBps(failure, currentBps)` gives that tolerance, capped at the new `PAY_MAX_SLIPPAGE_BPS` (10%, Signa's `prepare_pay` cap). `PAY_DEFAULT_SLIPPAGE_BPS` exports `prepareUserPay`'s default. Router, permit, Permit2 and NFT overspending messages now name the check that failed.

The write hold releases a direct write as soon as its own transaction's receipt shows it reverted in a canonical block, instead of waiting for finality, so the payer can review and send again at once (`HELD_FAILED_LINE`). Pending, unknown and succeeded writes hold as before, a revert whose block the node can't show canonical stays held, and a Safe failure still waits for finality. `verifyDefifaNftTransaction` classifies a direct revert the same way.
