Review gaps found moving juicebox-money onto the reviewed path. `useReviewedRun` keeps the value a failed run threw, with its cause chain, as `failure` (null on success and cancel), so a site can decode it (a slippage retry, say) beside the friendly `error`. A Safe-connected wallet reuses a proposal its Safe already queued for exactly the reviewed call (same Safe, chain, target, value, calldata, and a zero-refund CALL) instead of proposing it again; a near match is never reused, and a queue that can't be read, or doesn't answer within the hold's 8-second service bound, sends nothing. The queue is read through the write hold's Safe service (now exposed as `hold.safeService`), and the adopted proposal's nonce is held so its execution can be proven onchain. `findPendingSafeAppProposal` takes `exact` to find only a proposal of exactly the call, stamp included. `ReviewContextRow` takes `lines` (a value over several lines) and a `note`, both bound into the model's id. `buildReviewModel` never throws: a request it can't read or bind exactly gets a model with an `unreadable` warning (a new `ReviewWarningCode`), the parts it could read, and an id that matches no other model; core's own review prompt refuses such a model before any handler sees it, so it never sends or signs. `/review/decode` exports `addressLabel` and `currencyLabel`, and `/testing` exports the review fixture requests as `REVIEW_REQUESTS`.
